# Pinned dependency set for CI ("lockfile").
#
# WHY THIS FILE EXISTS
# --------------------
# pyproject.toml declares every dependency with a floating range
# (e.g. fastapi>=0.115.0,<1.0.0) and there is no lockfile, so CI resolved the
# newest-compatible release of ~76 packages on every single run. Combined with
# `filterwarnings = ["error"]` in [tool.pytest.ini_options], that makes any
# upstream release that introduces a NEW warning a hard CI failure with zero
# change on our side.
#
# That is not hypothetical: starlette 1.2.0 (2026-05-28) began emitting
# StarletteDeprecationWarning from `starlette.testclient` when httpx (rather
# than httpx2) is installed. filterwarnings=error promoted it to an exception
# and test_websocket_accepts_valid_ticket started failing on unchanged code.
#
# Installing with `-c constraints.txt` makes the resolved set deterministic, so
# a dependency release can no longer break main on its own. Upgrades become an
# explicit, reviewable edit to this file instead of a silent event.
#
# HOW TO REGENERATE
# -----------------
# In a clean Linux / Python 3.12 venv (matching the CI runner):
#     pip install -e ".[dev]"
#     pip list --format=freeze --exclude attendance-v2-backend > constraints.txt
# then re-add this header. Bump deliberately and let CI verify the new set.
#
# NOTE ON PLATFORMS: constraints only cap versions of packages that are
# actually selected for install; they never force one in. Linux-only entries
# (uvloop) are simply inert on other platforms, so this file is safe for local
# use on macOS/Windows as well.
